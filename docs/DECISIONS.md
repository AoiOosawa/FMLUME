# FMLUME — 設計判断ログ

書式: 日付 / 案 / 採用案 / 理由 / 互換性影響。

## D-001 プラグイン固定ID（2026-11-23）
- 採用: `PLUGIN_MANUFACTURER_CODE = Fmlm`、`PLUGIN_CODE = Fmlu`、`BUNDLE_ID = com.fmlume.FMLUME`、`COMPANY_NAME = FMLUME`、AU type `aumu`（MusicDevice）、VST3 category `Instrument|Synth`。
- 理由: SPEC §2 が初期実装時に一意な固定値を決めることを要求。
- 互換性: **公開後は変更不可**（DAWプロジェクトがプラグインを見失う）。未公開の現時点では変更可能。配布主体（会社名・ドメイン）が決まったら公開前に一度だけ見直すこと。

## D-002 FMLUMECore は JUCE 非依存（2026-11-23）
- 案: (a) Core が `juce_core`/`juce_dsp` に依存 (b) Core は標準C++20のみ。
- 採用: (b)。JSON・WAV・SMF・オーバーサンプリング（ハーフバンドFIR）を自前実装。
- 理由: JUCEモジュールはリンク先ターゲットごとにソースがコンパイルされるため、static lib と plugin の両方に入れると重複/ODRの危険がある。Core単体のビルドとテストが数秒で済み、ホストなしテスト（SPEC §15）が確実になる。
- 互換性: なし。

## D-003 テストフレームワーク（2026-11-23）
- 案: JUCE UnitTest / Catch2 / 自前の最小ハーネス。
- 採用: 自前ハーネス（`tests/TestFramework.h`、約40行）＋CTest。
- 理由: D-002 により Core は JUCE を持たない。Catch2 は追加依存とネットワーク取得が必要。必要な機能は `CHECK`/`CHECK_NEAR` とグループ実行のみ。
- 互換性: なし。SPEC §2 の「JUCE UnitTest または Catch2」からの逸脱（SHOULD相当と判断）。

## D-004 モジュレーションソースはグローバル（2026-11-23）
- 採用: LFO×2・ModEnv はエンジン側（A/B）ごとに1系統のグローバル。Velocity / Keytrack ソースは「最後に発音したノート」の値。オペレーター自身の `velocityToLevel` / `velocityToIndex` と各オペレーターADSRはボイス単位。
- 理由: SPEC §5.3 が初期版を「グローバルMod Envのみ」と規定。フィルターもグローバルなので、制御信号を1系統にすると32サンプル周期の評価が1回で済み、ブロックサイズ非依存の出力を保証しやすい。
- 互換性: 将来ボイス単位モジュレーションを追加する場合、Preset schema に `scope` を足す形で後方互換にできる。

## D-005 パッチ受け渡しは「最新優先メールボックス」（2026-11-23）
- 案: (a) 固定長SPSC FIFO (b) 事前確保スロット4個＋`{slotId, generation}` を1個のatomicで渡す最新優先メールボックス。
- 採用: (b)。オーディオスレッドはCASでスロットを取得し、自分のリングスロットへPODコピー（約20KB）してから解放する。裸ポインタの共有・解放待ちは発生しない。
- 理由: パッチは「最新だけが意味を持つ」ため、オーディオ停止中にFIFOが詰まる問題を避けられる。`forceNewGeneration` は未消費のまま上書きされても引き継ぐ（sticky）。SPEC §3.1 の「スロットIDと世代番号を渡す・破棄は非RT側」を満たす。FIFOではない点が文言上の差異。
- 互換性: なし（内部実装）。

## D-006 パッチ世代とインプレース更新（2026-11-23）
- 採用: オーディオ側に10スロットのリング（現行＋旧9世代）。構造（グラフ・有効オペレーター・波形・B有無・Morphモード）が同じで `forceNew=false` の編集は現行スロットを**インプレース更新**（発音中ノートにも滑らかに反映）。プリセット読込・Explorer試聴・構造変更は**新世代**（新ノートのみ新パッチ、既存ノートは旧パッチのままリリース）。
- リングが一周して使用中スロットに当たる場合、そのボイスを10msでフェードアウトし、空くまで適用を次ブロックへ延期する（SPEC §3.1 の8世代上限に対応）。
- 理由: ノブ操作のたびに新世代にすると、押さえている音に編集が効かず操作感が悪い。

## D-007 セルフフィードバックは直前2サンプルの平均（2026-11-23）
- 採用: `mod += feedback * 0.5 * (y[n-1] + y[n-2])`。
- 理由: SPEC §4.1 は「必ず前サンプル値を参照」「ナイキスト付近の発振に防御」を要求。n-1 単独では高フィードバック時にナイキスト周波数の発振（ハンティング）が出るため、過去値のみを使う2点平均で抑える（DX系の定石）。出力は env×level ≤ 1 で有界。
- 互換性: FM内部計算単位（radian）は不変。

## D-008 ボイス終了判定はキャリアのみ（2026-11-23）
- 採用: 「有効なキャリアのエンベロープがすべて無音」でボイス解放。モジュレーターのリリースが長くても、キャリアが無音なら出力は0なので待たない。Release上限は41秒。
- 理由: SPEC §4.3 は「全キャリアと有効モジュレーター」とするが、聴感上同一でCPUを節約できる。逸脱として記録。

## D-009 オーバーサンプリングとレイテンシ（2026-11-23）
- 採用: エンジンを内部レート（1x/2x/4x）で直接合成し、線形位相ハーフバンドFIRでデシメーションのみ行う（アップサンプリング不要）。2x→1x は47タップ、4x→2x は19タップ。
- レイテンシ（ホストサンプル）: Eco 0 / Standard 11 / High 13。これにFXチェーンの固定7（D-011）を加えた **7 / 18 / 20** を `setLatencySamples` で報告。
- 品質切替: 全ボイスを5msフェード→無音になったブロック境界で切替。バッファは最大4x分を `prepare` で確保済みで再確保なし。報告レイテンシはメッセージスレッドのタイマー（15Hz）が追従。

## D-010 プリセットが変更するホスト値（2026-11-23）
- 採用: プリセット読込で適用するのは `macro.1-8`、`fx.quick.*`、`master.polyphony/unison/detune/spread`、`morph.amount/enabled`、`arp.enabled`、`tranceGate.enabled`。
- **適用しない**: `master.gainDb`、`master.pan`、`master.quality`、`fx.bypassAll`（セッション設定）。これらはDAWプロジェクト状態には保存・復元される。
- 理由: プリセット切替でマスター音量や品質（レイテンシ）が跳ぶのを避ける。真実の所在は SPEC §13 のとおり APVTS。プリセット固有の音量は `output.levelDb`（Canonical Model）。

## D-011 Drive の2倍オーバーサンプリングは固定レイテンシ（2026-11-23）
- 採用: Drive は線形位相ハーフバンド（15タップ×2）で2x処理し、遅延は7サンプル。**Drive が無効・全FXバイパス時も同じ7サンプルの純ディレイを通す**ため、プラグインのレイテンシは設定によらず一定。
- 理由: FXのオン/オフでホスト報告レイテンシが変わると、再生中に補正がずれる。SPEC §10.1「オーバーサンプリング使用FXは内部遅延を報告」に対応。
- gain の最初の5%でシェイパーをフェードインするため、gain=0 は完全に透明。

## D-012 FXチェーンの再構成はディップ（2026-11-23）
- 採用: 順序・有効状態・全バイパスの変更時、チェーン出力を5msでフェードアウト→入替→5msでフェードイン。各FXの内部状態（残響）は並べ替えでは保持、新たに有効化されたFXのみリセット。
- 理由: 真のクロスフェードには全FXの状態を二重化する必要がある。SPEC §10.1 は「可能なら状態維持、段差は10msのクロスフェードで抑える」。瞬間的な無音ディップになる点が差異。

## D-013 パラメーターIDの番号付け（2026-11-23）
- 採用: マクロ/Mod Matrix のターゲットIDはオペレーター番号を**1始まり**で表記（`op1.level`、`edge.1.2.index`）。JSON の `edges[].from/to` は SPEC §12.2 どおり**0始まり**。
- 互換性: **公開後は変更不可**（プリセット互換）。全IDは `docs/PRESET_SCHEMA.md` に列挙。

## D-014 schemaVersion 0 のマイグレーション（2026-11-23）
- 採用: 開発中レイアウト（単一 `engine`、B系キーと `output` なし）を schema 0 として定義し、`migrate0to1` で読込時に変換。未知の将来バージョン（>1）は安全に拒否。
- 理由: SPEC §12.1 の「schemaVersionごとにmigration関数」「旧版でクラッシュしない」（PRS-03）を実際に動く経路として持つため。

## D-015 ポルタメントを共有パラメーターコードに追加（2026-11-23）
- 採用: `performance.portamento`（0〜2s）をマクロターゲット可能な共有パラメーターとした（Lead の「Glide」マクロ用）。Mod Matrix のターゲットではない。

## D-016 演奏機能の順序と細部（2026-11-23）
- 採用: MIDI → Chord → Arp → Voice Allocator。Arp はコード展開後の全ノートを対象。Strum は構成音ごとの遅延（k番目 = k×strumMs）。ホスト停止中/位置不明時は内部クロックでフリーラン（最初の打鍵で即ステップ0）。再生開始・位置ジャンプ・（設定時）停止でパターンをリセットし、鳴っているArpノートを先にNoteOffする。
- スウィング: 奇数ステップを `swing × stepLength × 0.5` 遅らせる（最大60%→0.3ステップ）。

## D-017 Morph のゲインはボイス単位・フィルター前（2026-11-23）
- 採用: Dual Morph の等パワーゲイン（cos/sin）は各ボイスの出力に掛けてから A/B それぞれのバスとフィルターへ送る。Morph種別（Off/Compatible/Dual）はノートオン時にボイスへラッチ。
- 理由: `morph.enabled` 切替やプリセット交代で発音中の音を切らないため。フィルターDrive使用時のみ「フィルター後クロスフェード」と僅かに異なる。m=0/1 で A/B 単体と一致（MOR-01、誤差 < 1e-5）。

## D-018 お気に入りはユーザー設定に保存（2026-11-23）
- 採用: `~/Library/Application Support/FMLUME/Presets/favorites.json` に patchId の配列で保存。プリセットファイルの `favorite` フィールドは読み書きするが参照しない。
- 理由: ファクトリープリセットは読み取り専用（SPEC §12.1 が許容）。

## D-019 Dual Morph × High(4x) のボイス予算（2026-11-23）
- 採用: 通常はエンジンあたり64 SubVoice（Dualは計128演算単位）。**Dual かつ 4x のときのみエンジンあたり32**に制限。
- 理由: 実測で Dual+8×8 unison+4x は1ブロック最悪112%に達した。SPEC §17.3「音切れよりも安全に発音数を制限」。制限後は平均56%・最悪86%（M1 Max）。UIに実効最大ノート数を表示。

## D-020 ファクトリープリセットは生成ツールで作成（2026-11-23）
- 採用: `tools/PresetGen`（`fmlume-presetgen`）が108音色を構築し、全マクロ・全Quick Controlの可聴性を検証、ラウドネスを揃えて `Resources/Presets/*.fmlume` に書き出す。プラグインには `juce_add_binary_data` で埋め込む。
- 理由: 音色定義をコードレビュー可能にし、スキーマ変更時に一括再生成できる。すべて自作のFM設計で、既存製品のパッチ・サンプルは不使用。

## D-021 Morph 互換条件から Unison 数を除外（2026-11-23）
- 採用: Unison 数はホストパラメーター（A/B共有）なので常に一致。互換条件は「グラフ・有効オペレーター・波形・PitchMode・KeySync・キャリア構成・フィルタータイプ」の一致。

## D-022 スロットBのマクロはFXを動かさない（2026-11-23）
- 採用: FXはMorphパッチ全体で1系統。`macrosB` 内のFXターゲット・`matrixB` のFXターゲットは無視（A側のみ有効）。Quick Controls はA/B共通。

## D-023 Explorer の対象はスロットA（2026-11-23）
- 採用: 候補生成はスロットAの音源・マクロ・Mod Matrix・共有FXを変化させる。採用（Use）してもスロットBとホスト値は保持。候補名は親とのスコア差からの推定（Brighter 等）で、知覚を保証しない旨をUIに明記。

## D-024 出力リミッター（2026-11-23）
- 採用: |x| ≤ 0.9 は完全に素通し、それ以上は 1.0 を上限とするソフトニー。ファクトリープリセットは通常演奏でリミッターに触れないレベルに調整。

## D-025 開発用UIスナップショットツール（2026-11-23）
- 採用: `-DFMLUME_BUILD_UI_SNAPSHOT=ON` で `fmlume-uisnap`（エディタをオフスクリーン描画してPNG保存）をビルドできる。既定OFF・配布対象外。（当初は「Standalone形式は製品に含めない」としていたが D-026 で変更）

## D-026 Standalone 形式を追加（2026-11-23）
- 採用: `juce_add_plugin` の `FORMATS` に `Standalone` を追加し、`FMLUME.app` を生成する。ユーザーの要望による。DAWなしで音色確認・試聴ができる。
- 実装: JUCE 標準のスタンドアロンラッパー（`StandaloneFilterWindow`）をそのまま使用。Audio/MIDI 設定は Options メニュー。プロセッサー・エディタ・パラメーターID・状態形式は AU/VST3 と完全に同一。入力バスがないためマイク権限は要求しない。
- 後方互換性: 影響なし（AU/VST3 のID・状態・パラメーターは不変）。SPEC §1 の対象形式（AU/VST3）への追加であり、置き換えではない。

## D-027 Trance Gate のパターン集を POLYBRISK と共通化（2026-11-23）
- 採用: `Source/DSP/Sequencer/GatePatterns.h` に POLYBRISK の `factoryGatePatterns` と同じ名前・グループ・ステップ列を持つ表を置き、Simple の TRANCE GATE と Advanced > Rhythm の Pattern で選べるようにした（44 パターン）。選ぶとそのパターンが前提とする Rate（1/16 または 1/32）も設定する。
- 含めなかったもの（当初）: POLYBRISK の「Stereo」グループ7種と 1/64 前提の「Chop Tail」。→ D-030 でステレオ化と 1/64 に対応し、全52パターンを収録した。
- 後方互換性: 影響なし。プリセットにはステップ値と Rate だけを保存し、パターン名は保存しない（表示名はステップ列との照合で決まり、一致しなければ「Custom」）。以前の6種の簡易パターン（Eighths など）は廃止したが、保存済みプリセットのステップ値はそのまま読める。

## D-028 UI の全面改訂: POLYBRISK とシリーズ共通の外観（2026-11-23）
- 理由: ユーザーレビュー（シリーズ感がない / Explore と Morph の使い方がわからない / CPU 表示がちらつく / Operators のノブが多すぎる / Algorithm 表示が馴染みにくい / Advanced が急に難しい / ブラウザを独立させたい）。
- 採用:
  - 配色・パネル・ノブ・ロッカースイッチ・タブ・ヘッダー構成を POLYBRISK と共通化。基調色のみ変更（POLYBRISK = オレンジ、FMLUME = シアン→バイオレット）。
  - プリセットブラウザを独立ページ化（ヘッダーのプリセット名で開閉）。Fav / File ボタンはブラウザへ移動。ユーザープリセットの Delete を追加。
  - Explore → 「Variations」: Generate → タイルをクリックして試聴（テストコードが自動で鳴る）→ Keep this sound の3段階。Lock は「Keep unchanged...」メニューに集約。
  - Morph: A / B のカードとスライダー。B はブラウザから直接選ぶ（「ブラウザで選択してから Load B」を廃止）。モード名は Auto / Smooth（= Compatible）/ Layered（= Dual）と表示。
  - CPU / Voice 表示を削除。出力メーターは OUT スライダー下の細いバーに。
  - Operators: 6枚のカード（ミニエンベロープ、レベルバー、役割、電源）＋選択中の1オペレーターだけを編集（波形表示、ドラッグできるエンベロープ）。常時見えるノブは 78 → 13。
  - Algorithm: テンプレート18種をサムネイル一覧で表示し、DX 風（キャリア下段・OUT バー・モジュレーター上段・フィードバックループ）のダイアグラムに変更。ドラッグ接続は維持。
  - Advanced のタブを Operators / Algorithm / Filter & Mod / FX / Rhythm / Performance に再編。これまで UI から編集できなかったフィルター（Type / Cutoff / Resonance / Drive）のパネルを追加。
- 既知の制約: Morph の B 側の音色名はセッション内だけ保持する（Preset schema に保存場所がないため、再読込後は「Second sound」と表示）。Variations の「Keep unchanged」設定もセッション内のみ。
- 後方互換性: 影響なし。ホストパラメーターID・Preset schema・状態形式・DSP は不変（UI とパターン表のみの変更）。

## D-029 ロゴとアイコン（2026-11-23）
- 採用: POLYBRISK と同じタイル・線の太さ・配色体系で、モチーフを「デチューンした鋸歯状波」から「周波数変調されたサイン波（＋モジュレーターとキャリアのゴースト）」に置き換えたマーク。`assets/branding/`（icon.svg / icon-1024.png / FMLUME.icns / logo-mark / wordmark）。SVG は `tools/branding/make_assets.py` が生成し、UI 内のマーク（`ui::drawLogoMark`）も同じ式で描く。Standalone のアプリアイコンに設定（`ICON_BIG`）。

## D-030 Trance Gate のステレオ化と Preset schema の追加項目（2026-11-23）
- 理由: ユーザーの要望（POLYBRISK と同じステレオゲート）。
- 採用:
  - モデル `TranceGateState` に `stereo` / `stepsRight[16]` / `width` を追加。DSP は左右別のゲインを持ち、`stereo` が偽なら従来どおり左右同一。Width の挙動は POLYBRISK と同じ（下げると左右とも「大きい方」に寄り、リズムは残って定位だけ中央に寄る）。
  - ゲートの Rate に 1/64 を追加（アルペジエーターは変更なし）。
  - パターン集に Stereo グループ7種と「Chop Tail」（1/64）を追加し、POLYBRISK と同じ52種に。Stereo のパターンを選ぶと `stereo` が ON になる。
  - UI: Advanced > Rhythm に Stereo スイッチと Width ノブ、ステップグリッドは Stereo 時に L / R の2段。
- **Preset schema への影響**（「schema を変更しない」原則の例外。ユーザー指示による）:
  - `performance.tranceGate` に省略可能なキー `stereo` / `stepsRight` / `width` を追加し、`rate` の列挙に `1/64` を追加。`schemaVersion` は 1 のまま（未公開のため。既存キーの意味・必須項目は不変）。
  - 後方互換（旧→新）: 既存の108ファクトリープリセットと旧形式のユーザープリセット・DAW状態は変更なしで読める（省略時はモノラル）。モノラルのプリセットは従来と同じ形で書き出される。
  - 前方互換（新→旧）: ステレオゲートや 1/64 を使ったプリセットは、この変更より前のビルドでは未知キー／未知の値として拒否される。公開済みのビルドは存在しないため実害はないが、公開後に同種の追加を行う場合は `schemaVersion` を上げること。
- ホストパラメーターIDは不変（`tranceGate.enabled` のみ。Stereo / Width はプリセット側の値）。

## D-031 アルゴリズム表示の判定を緩和（2026-11-23）
- 理由: プリセットを切り替えたとき、多くの音色が「Custom routing」と表示され、どのアルゴリズムか分からなかった（未接続のオペレーターが ON のまま、あるいはテンプレートと同じ形でも番号の振り方が違うと不一致になっていた）。

## D-051 ボイス合算の直後に DC カットを入れる（2026-11-23）
- 経緯: ファクトリー音色のスクリーニング（`scripts/audition.py`）で、19 音色の出力に直流成分が見つかった。最大は Epic Low Brass で、発音中の DC が RMS とほぼ同じ大きさ（比 0.97）。1:1 の位相変調とオペレーターのフィードバックは原理的に DC を生む（ハードウェア FM 音源は出力が AC 結合なので問題にならない）。
- 害: ヘッドルームを消費する、発音・消音時にクリック/ポップになる、後段の Drive / Compressor が偏って動く、音量の自動補正（ピークと RMS）が実際の音量とずれる。
- 採用: `SynthEngine` で、各サイド（A / B）のボイス合算・デシメーションの後、フィルターと FX の前に 1 次のハイパス（5 Hz）を入れる。27.5 Hz（A0）での減衰は約 0.15 dB。オペレーター間の変調信号には手を入れない（音色が変わるため）。
- 影響: 音色は可聴域では変わらない。DC が乗っていた音色は音量補正値が変わるため、`fmlume-presetgen` で再生成（152 音色中 61 の `output.levelDb` が変化）。カテゴリーテンプレートの音量（`kTemplateLevelDb`）も E.Piano / Bass / Lead / Pad を再測定値に更新。プリセットの形式とパラメーター ID は変更なし。
- 同時に: Acid Square の Growl マクロ（レゾナンスとドライブ）が最大で +16.6 dB になっていたため量を半分にした（+8.8 dB）。

## D-056 Import はユーザープリセットとして取り込む。一覧の ID は必ず一意にする（2026-11-24）

  - **Import**: ファイルをユーザープリセットとして保存してから読み込む（`PresetManager::importIntoUser`）。新しい ID を振り、名前はファイルの `displayName`（同名のユーザープリセットがあれば「名前 2」「名前 3」…）。ブラウザーは開いたままで、取り込んだプリセットが一覧に現れる。以前の「読み込むだけ。残すには Save」という動作は廃止。
  - **ユーザーフォルダーの走査**: 手で置かれたファイルがファクトリーや他のユーザーファイルと同じ ID を持つ場合、一覧上の ID をファイル名から作ったものに置き換える（`user-file.<ファイル名>`）。読み込んだプリセットもその ID になる。ファイル自体は書き換えない。
- 影響: プリセット形式の変更なし。Export の動作は変更なし（書き出したファイルは元の ID を保つ）。
- 確認: 自動テスト（編集したファクトリープリセットの書き出し→取り込みで別の ID のユーザープリセットになること、ファクトリー側が変わらないこと、同じファイルの再取り込みで番号付きになること、ID が重複するファイルの扱い）。スタンドアロン版の画面で利用者が Export → Import を試し「問題なし」と確認（2026-11-24）。

## D-057 Algorithm タブを Operators タブに統合する（2026-11-24）
- 利用者の要望。経緯: FM ではオペレーターの設定の意味が結線で決まる（同じ Level でもキャリアなら音量、モジュレーターなら明るさ）のに、結線は別タブに切り替えないと見えなかった。Algorithm タブには Operators タブと重複するノブもあった。
- 採用（利用者と画面を見ながら段階的に決定）:
  - Operators タブの上段に編集できる結線図（ドラッグで接続、箱で選択、線をクリックして深さと削除、オペレーターのオン/オフ）。右側に選択中オペレーターの役割の説明、接続の深さ、`Fit macros 1-4 to routing`。下段は選択オペレーターの Oscillator / Envelope / Level & Response。
  - 6 枚のオペレーターカードは廃止（結線図が選択を兼ねる）。
  - 波形とエンベロープのグラフは縦横比を固定（3:1、2.4:1）し、ウィンドウの大きさで形が変わらないようにした。下段は中身ぴったりの高さで、残りを結線図に回す。
  - テンプレート 18 種は `Templates...` のポップアップ。`Expand` で結線図をタブ全体に広げ、テンプレートを一列に常時表示し、右側に選択中オペレーターの Ratio / Level / Output / Feedback を出す（下段が隠れるので重複にならない）。
  - 結線の深さの数値は、線・箱・フィードバックのループ・他の数値に重ならない位置に自動で置き、置けなければ省く。図の大きさはフィードバックのループと OUT の文字まで含めて収まるように計算する（ループが図からはみ出す不具合の修正）。
  - 凡例は ROUTING の見出しの行へ。結線図のツールチップは図を隠すので廃止。
  - `Rebuild macros 1-4` を `Fit macros 1-4 to routing` に改名。結果が今の割り当てと違うときだけ確認を出す（Macro Editor で設定したマクロ 1-4 の割り当ては置き換わるため）。
- 影響: Advanced のタブは 6 → 5。プリセット形式・パラメーターには影響なし。
- 確認: ビルド、`ctest`、auval、pluginval、`fmlume-uisnap`（通常・最小サイズ、拡大の有無、フィードバック付きの結線 3 種）、キー操作の検査。テンプレートのポップアップ、拡大の切り替え、図の上のドラッグ操作、確認ダイアログは実機での確認がまだ。
